Menu mode (full vs. limited menu)

On busy event days the website shows a shorter limited menu instead of the full menu. The Menu Mode page shows which one is live right now.

  • Automatic (normal setting) — follows the events calendar. The limited menu starts a set number of hours (usually 2) before an event's start time, or all day if the event has no time. Only events with Limited menu ticked count.
  • Force Full Menu — always show the full menu, e.g. if a game is cancelled.
  • Force Game Day Mode — show the limited menu now, e.g. for an unexpected rush.
{% if staff_is_manager %}

Click an option to switch. Remember to switch back to Automatic afterwards — a forced mode stays on until someone changes it.

{# ── Events ─────────────────────────────────────────────────────────────── #}

Events calendar

Games, private parties, live music and holidays. Events control when the limited menu is used (see Menu mode) and appear on the public events calendar.

{% if staff_is_manager %}

Add an event

  1. Events → + Add Event.
  2. Choose the date and type. For games, pick the team and home or away.
  3. Add a start time if there is one — the limited menu starts a couple of hours before it. Leave it blank for all day.
  4. Label is optional — it replaces the default name (e.g. “Steelers vs. Ravens”).
  5. Save.

Home games get the limited menu automatically; away games don't. To use the limited menu for an away game (say, a watch party), edit the event after saving and tick Limited menu. Untick it for events that keep full service, such as most live music.

To load a whole schedule at once, or change many events, use Import / Export CSV on the Events page — see Events spreadsheets.

Change or remove an event

  • Edit — change any detail.
  • Deactivate — hide the event and stop it affecting the menu, without deleting it. Activate brings it back.
  • Delete — remove it for good.

{# ── How menus work ─────────────────────────────────────────────────────── #}

How menus work

A dish never goes straight onto a menu. It travels through four layers:

Menu item → placed in a category (optionally under a subcategory) → categories are shown on a menu → the site picks which menu customers see.

For example: Classic Burger is placed in Burgers; Burgers is on the Food Menu; the Food Menu is the default food menu, so it's what customers see on the Food page.

1. Menu items — the dish or drink itself

An item is written once and can appear in as many places as you like. What it holds:

  • Name, a short description (shown in menu listings) and a longer description (shown when a customer taps the item).
  • Price and how it's shown: Show price, Market price (shows "MP") or Hide price (shows nothing — handy for drinks).
  • Sale price — when set and lower than the price, customers see the old price crossed out next to the sale price.
  • Sizes (e.g. Pint / Pitcher) and add-ons (e.g. Add bacon +$2) — see Sizes and add-ons below.
  • Badges: Featured, Chef's special, New and Seasonal.
  • Dietary — the dietary type (Vegetarian, Vegan, Gluten free, Dairy free) plus the Gluten-free, Dairy-free and Nut-free ticks, shown as labels when the item is tapped.
  • Allergen info — extra warnings shown when the item is tapped.
  • Available — the master switch. Turning it off hides the item everywhere, on every menu.
  • Photos — chosen from the media library (Menu Items → Images).

Some item settings are stored but not shown on the website yet: the separate Vegan tick (use the Vegan dietary type instead), Contains shellfish, spice level, calories, preparation time, and the time-of-day or day-of-week limits. Changing them has no effect on what customers see for now.

Sizes and add-ons

Both belong to the item, so they're the same everywhere the item appears. They're for information only — customers see them when they tap the item; nothing is ordered online.

Sizes (called variations in the spreadsheets) — for one item that comes in versions with different prices: Pint / Pitcher, Glass / Bottle, 6 / 12 wings.

  • Each size has a name (Pint), an optional size note shown in brackets (16 oz), a price, a position and an available switch.
  • When the item is tapped, an Options list shows every available size with its price, in position order. The item's own price isn't shown there.
  • In the menu listing, the item shows the range of its available size prices (e.g. $6.00 – $18.00), or a single price if they're all the same — but only if the item's Has variations box (has_variations) is ticked. If it isn't, the listing shows the item's normal price even though the sizes still appear when tapped.
  • A category's special price, or a Market / Hide price setting, replaces the range in the listing. The sizes keep their own prices when tapped.
  • Switching a size off hides it from the Options list and from the range.

Add-ons — optional extras: Add bacon, Extra cheese, Make it a double.

  • Each add-on has a name, a price (shown as "+$2.00"), a position and an available switch.
  • When the item is tapped, an Add-ons list shows every available add-on. They don't change the price shown in the listing.
  • They appear whenever the item has an available add-on — the item's Has addons box doesn't change anything on the website.

A size's description, quantity and "default" setting, and an add-on's description and "default" setting, are stored but not shown on the website yet.

{% if staff_is_manager %}

To add or change them, use the variations (sizes) and addons files in Menu import / export — one row per size or add-on, naming the item by its slug. Remember to set has_variations to yes in the items file so the listing shows the price range. The Whole menu sheet doesn't include sizes or add-ons.

{% endif %}

2. Categories — the sections of a menu

  • A category is a section such as Burgers, Beer or Happy Hour Drinks, marked as food or drinks.
  • Name is for staff. Display name is the heading customers see — leave it blank and the section has no heading at all.
  • Optional description, background image (with a dark overlay so text stays readable) and a disclaimer line at the bottom of the section.
  • Active off hides the category everywhere, whichever menus it's on.

3. Subcategories — optional groups inside a category

  • Used to split a long category, e.g. Beer → On Tap / Bottles & Cans, or Wine → Red / White.
  • Each belongs to one category and has its own position within it.
  • As with categories, the display name is the sub-heading; blank means no sub-heading.

4. Placing an item in a category

Putting an item into a category (a placement) has a few settings of its own — they apply to that category only:

  • Subcategory — which group it sits under (optional).
  • Position — where it appears in the category.
  • Special price — a different price in this category only (e.g. half price in Happy Hour Drinks). The item's normal price is untouched everywhere else.
  • Note — a short call-out shown on the item here, e.g. "Limited time!".
  • Shown — turn off to hide the item from this category without removing it.

Which price customers see: a special price wins; otherwise "MP" or nothing if the item is set to Market / Hide price; otherwise the size range; otherwise the sale price; otherwise the normal price.

5. Menus — collections of categories

  • A menu lists the categories it shows and in what order. Every item in those categories comes along with them.
  • Title is for staff; display name is what customers see (blank = use the title).
  • Type: Food, Drinks, Promotion or Weekly specials.
  • Active switch, plus optional active from / until date-times to schedule it.
  • Role — marks the menu as the default food, default drinks, event food or event drinks menu. Only one menu can hold each role; giving a role to a new menu takes it away from the old one.
  • Promotions can have a color scheme and a homepage slot (left or right of the main banner). Food, drinks and specials menus always use the site's normal colors.
  • Weekly specials have valid from / until dates and appear only between them — the "This week's specials" link shows up by itself and disappears when the dates pass.

6. Which menu customers see

  • The website's Menu → Food and Menu → Drinks pages show the menus with the default food and default drinks roles.
  • During limited-menu times (see Menu mode) they switch to the event food and event drinks menus instead.
  • Menu → Event Day (Limited) always shows the event menus, so customers can see them ahead of a game.
  • Promotions appear on the Promotions page (/menu/promotions/) while active and within their dates.
  • Homepage slots show a promotion whenever it's switched on — they don't follow its dates, so switch it off or clear its slot when the promotion ends.

Good to know

  • Shared categories: a category on two menus shows the same items on both. To show an item on one menu only, give that menu its own category (e.g. "Promo Burgers").
  • One item, many places: the same dish can sit in several categories, each with its own position, special price and note.
  • Three ways to hide something: item not available (gone everywhere) · placement not shown (gone from that category) · category taken off a menu (that whole section gone from that menu).
{% if staff_is_manager %}

Setting up a new menu

Work from the bottom up, because each layer refers to the one before it:

  1. Create any new categories (and subcategories).
  2. Create any new items.
  3. Create the menu and choose its type (and role, color scheme or dates as needed).
  4. Add the categories to the menu, in order.
  5. Place the items in their categories.

The quickest way is the Whole menu sheet in Menu import / export: one row per item on the menu creates the menu, categories, items and placements together (subcategories must exist first). Deleting items and changing which days a promotion runs are done by a site administrator.

Event inquiries

Requests from the website's private-event form. Each new inquiry is also emailed to the restaurant's notification address, and the customer automatically gets a “we received your inquiry” email.

  • Use the status menu on each row to track progress: New → Contacted once you've reached out → Closed when it's booked or declined.
  • Filter by status at the top to see only what still needs attention.
  • Delete removes an inquiry for good.

Customers say whether they prefer a call or an email — check before reaching out.

Spam

Submissions that look automated — sent within seconds of the page loading, containing web links, or mostly in another alphabet — are filed under Spam (top right) instead of New, and no emails are sent for them. Each shows why it was flagged.

  • Glance at Spam now and then. If a real customer ended up there, change its status to New and contact them yourself — they did not get a confirmation email.
  • Delete spam whenever you like; it doesn't affect anything else.
  • If an unusual flood of inquiries arrives, the site keeps saving them but pauses inquiry emails for the rest of the hour, and emails you a warning.

Media library (photos)

Every photo on the site lives here. The public Gallery page shows only published photos.

Upload a photo

  1. Media Library → + Upload.
  2. Choose the file and give it a name you'll recognise (e.g. “Burger close-up summer”).
  3. Pick a category — it decides which gallery tab the photo appears under.
  4. Add alt text: a short description of the photo for visitors who use screen readers.
  5. The caption is shown to visitors when they open the photo.
  6. Tick Published to show it in the gallery straight away, or leave it hidden and publish later.

Lots of photos at once

Copy the files to the server's media/gallery/ folder (ask your site administrator how), then click Import from Disk. Imported photos start hidden, named after their file names.

Publish, edit, delete

  • Show / Hide on each photo publishes it to the gallery or takes it down.
  • Edit changes the name, category, alt text, caption and display order.
  • Delete removes the photo from the library. The file is kept in a deleted folder on the server, so an administrator can recover it.
  • A photo used elsewhere (a banner, popup or menu item) can't be deleted — the message tells you where it's used. Remove it there first.

Newsletter

Emails to everyone who signed up on the website and confirmed their address. Each email includes an unsubscribe link automatically.

Write and send

  1. Newsletter → + Compose. Enter a subject and write the message — you can add headings, lists, links and images.
  2. Save. This creates a draft; nothing is sent yet.
  3. Check the preview. Use Edit to make changes.
  4. When it's right, click Send Now and confirm. The message says how many people it went to.
  • Sending can't be undone. Clicking Send Now twice won't send it twice.
  • If sending fails completely (for example the mail server is down), the newsletter stays a draft — try again later.
  • Duplicate starts a new draft from an earlier newsletter.
  • Drafts can be deleted; sent newsletters are kept as a record.

Site popups

A message box that appears a few seconds after a visitor arrives — for an announcement, a special, or newsletter signups.

  1. Popups → + New Popup. The title is just for you; visitors see the heading and body.
  2. Either add a button (label and link), or tick Show email signup form to collect newsletter signups instead.
  3. Choose colors and how many seconds to wait before it appears.
  4. Save, then click Activate in the list.
  • Only one popup is live at a time — activating one switches off the others.
  • A visitor who closes the popup won't see it again until their next visit. People who have already subscribed never see it.
  • Deactivate it when the promotion ends.

Site settings and color schemes

Administrators only. Changes take effect on the site immediately.

Import / export (menu and events spreadsheets)

Managers and administrators. Change many menu items at once — prices, descriptions, a new promo menu, a seasonal change — or load a season of events, by editing a spreadsheet instead of clicking through the admin.

Change existing items

  1. Tools → Import / Export. Click Export next to the file you need (e.g. items).
  2. Open it in Excel or Google Sheets and edit. Leave the slug column alone — it's how each row finds its record.
  3. Save as CSV (in Excel: CSV UTF-8).
  4. Upload it, choosing the same file type. The preview lists every change as old → new.
  5. Confirm import to save, or Cancel.

The whole menu on one sheet

The Whole menu file has one row per item on a menu: menu, category, item, price and the usual flags. It's the easiest way to set up a new menu or make a seasonal change.

  • A menu, category or item name that doesn't exist yet is created. New menus need a menu_type (food, drinks, promo or weekly_specials).
  • price is the item's own price everywhere it appears. For a different price in one category only, use special_price.
  • An item can appear on several rows (in several categories or menus) — its price and flags must match on every row, or the import stops and shows both line numbers.
  • category_order and item_order set the display order; leave them blank to keep the current order (new entries go to the end).
  • shown = no hides an item in that category without removing it.
  • Subcategories must already exist — create them with the subcategories file first.

Add new things

Download the Template (a header row plus one example row), fill in a row per new record and upload it. Files depend on the ones above them in the list — import new categories before the items placed in them, and items before placements.

Sizes and add-ons have their own files, variations and addons: one row per size or add-on, with the item's slug in the item column. A row with the same item and name as an existing one updates it. See Sizes and add-ons for how they show on the website.

Events

The Events file has one row per calendar event: date, event_type (game, private_party, live_music, holiday, other), label, team, home_away, game_time, limited_menu, limited_menu_lead_hours and is_active. Events → Import / Export CSV opens it directly.

  • New events: leave id blank. Only date is required; the type defaults to a game.
  • Changing events: export first and keep the id column — that's how a row finds its event, even if you change its date. Without an id, a row updates the event with the same date, type, team and label, so uploading the same schedule twice doesn't make duplicates.
  • For new games, leave limited_menu blank to get the usual default (on for home games, off for away). Fill it in to override, e.g. yes for an away-game watch party.
  • Times can be 18:40 or 6:40 PM; blank means all day.
  • To cancel an event, set is_active to no. Delete events on the Events page.

Rules for cells

  • Blank keeps what's there now. Type - (a dash) to empty a field.
  • Yes/no columns accept yes/no, y/n, true/false or 1/0.
  • Prices are plain numbers: 12.50, no $ sign. Dates are month/day/year: 9/18/2027 — never day first. Date and time: 9/18/2027 17:30; times alone 17:30 (or 5:30 PM).
  • Choices accept the code or the label shown in the admin (default_food or Default Food Menu).
  • Refer to other records by slug; names work if only one record has that name.

Safety

  • Imports never delete. To hide something, set is_active or is_available to no.
  • If any row has an error, nothing from the file is saved — fix the file and upload again.
  • Photos aren't in the spreadsheets; manage them under Menu Items → Images.
